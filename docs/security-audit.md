# Security audit: v0.5.0

Review date: 2026-10-02. Scope: SSRF and redirect handling, path traversal, image decompression, SVG handling, response/header construction, regular expressions, and resource exhaustion. The findings below describe the code before the v0.5.0 fixes; disposition records the resulting control and regression coverage.

## Findings by severity

### High

| Finding                                                         | Evidence at review time                                                                                                                                             | Risk                                                                                                                          | Fix and regression coverage                                                                                                                         |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Animated/multipage image pixel budget counted only one page     | `src/security/limits.ts:19-38` reads width and height but ignores Sharp's `pages`/`pageHeight` metadata; GIF and TIFF are allowed at `src/security/limits.ts:4-11`. | A small frame repeated many times can exceed the configured decoded-pixel budget and consume disproportionate CPU and memory. | Count total frame pixels against `MAX_INPUT_PIXELS`; reject over-budget images. Tests cover multi-page pixel math and oversized animation metadata. |
| Batch ZIP downloads opened every stored result before streaming | `src/jobs/bullmq-batch-queue.ts:169-182` opened a stream for each result before constructing the ZIP stream.                                                        | Concurrent 100-item downloads could keep hundreds of file descriptors open per request and exhaust process limits.            | Open each result stream only after the previous ZIP entry finishes. A 100-item ZIP unit test verifies sequential stream opening. |

### Medium

| Finding                                                 | Evidence at review time                                                                                                                                                                                 | Risk                                                                                               | Fix and regression coverage                                                                                                                                                                                                                                       |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No Origin policy or API-wide authentication/scope check | `src/api/app.ts:33-37,80-87` configured Fastify and rate limiting without CORS or an API authentication hook; `src/api/routes/batch.ts:85-103` accepted anonymous uploads when no keys were configured. | A browser can submit simple cross-origin requests, and configured credentials had no route scopes. | Add exact-origin allowlisting and reject unlisted browser origins; authenticate configured API keys across `/v1/*`, authorize route scopes, and rate-limit by hashed key identity. Tests cover denied origins, preflight, missing/invalid keys, and scope denial. |
| API key configuration stored raw key values             | `src/security/api-keys.ts:3-24` hashed the presented key for identity but compared against hashes derived from configured plaintext keys.                                                               | Anyone who can read environment/config dumps can use the raw client credentials.                   | Configure SHA-256 key digests and compare digests in constant time. Tests cover digest-only configuration and invalid digests/scopes.                                                                                                                             |
| Responses lacked baseline browser security headers      | `src/api/app.ts:33-37,61-78` set request/error handling but no security response headers.                                                                                                               | Browser embedding, content sniffing, and referrer behavior relied on client defaults.              | Add Helmet-equivalent headers in an `onSend` hook. Integration tests assert headers on success and errors.                                                                                                                                                        |

### Reviewed; no exploitable finding

- **SSRF, DNS rebinding, redirect chains:** `src/security/ssrf.ts:67-126` resolves and validates every hop, pins each request to a checked address, and limits redirects. `src/security/webhook.ts:29-79` validates and pins the same resolved address. Regression tests cover private/mixed DNS answers, redirect-to-private, and same-host DNS rebinding.
- **Path traversal:** `src/storage/disk-storage.ts:170-172` hashes storage keys before constructing paths; batch ZIP entry names are generated from item indexes in `src/jobs/batch-processor.ts:65`. Tests cover hostile keys and ensure response filenames are fixed.
- **SVG script injection:** user SVG is not an accepted image input. Text watermarks escape XML metacharacters in `src/core/engine.ts:341-375`, and image watermarks require PNG magic bytes at `src/core/engine.ts:265-275`; all outputs are raster formats. Regression tests reject SVG input and SVG watermark payloads and verify text is rasterized.
- **Header injection:** `Content-Disposition` is a fixed server constant in `src/api/routes/batch.ts:321-327`; webhook header names/values are fixed or generated from numeric/HMAC values in `src/security/webhook.ts:107-112`. Tests assert hostile job values cannot inject headers.
- **ReDoS:** user-facing validation expressions in `src/api/schemas/operations.ts` and `src/security/limits.ts:54-92` are fixed, bounded character-class or prefix checks; there are no user-supplied regular expressions or nested ambiguous quantifiers. Watermark text and operation-chain length have explicit schema limits.
- **General concurrency:** `src/api/app.ts:50-59` caps active HTTP requests, `src/security/concurrency.ts:10-27` limits image processing, and `src/config/index.ts:126-163` bounds memory/pixel budgets. Queue concurrency and per-key admission limits are separately configured.

## CI and dependency checks

CI runs `npm audit --audit-level=high` after `npm ci`. The CodeQL workflow scans JavaScript/TypeScript on pushes, pull requests, and its scheduled run. Review the Dependabot alerts and rerun the audit when dependencies change.
